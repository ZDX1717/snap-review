# DESIGN 修订历史(v1~v21 归档)

> 从 `zquiz/DESIGN.md` §0 迁出(👤 2026-09-12:"设计规范太冗长")。
> 正文里仍然有效的**规则**都已并进 DESIGN.md 的对应章节;这里只保留"当时改了什么、为什么"的过程记录。

- v21(2026-09-12):**题库设置重新排版**(👤 要求"重新规划排版,按钮形状大小可自行更改")。旧的"三行混排按钮"改成**按作用对象分块**:卡片配色 / 本库 / 全部题库 / 错题本 / 版本记录 / 危险操作;每块一个小标题,标题即目录。要点:① **「删除题库」独占最底部的危险区**(淡红底 + 红标题 + 红描边按钮),不再和重命名/导出同排 —— 这是"两类动作不同屏"的延伸;② 设置页按钮改成自己的一套 `.admin-btn`(描边圆角方框,桌面 40px / 手机 44px,`min-width:150px`),桌面按内容宽**不撑满整行**,手机 `flex:1 1 140px` **填满整行**;③ 版本记录改用宿主容器 `#editor-versions-host` 挂载(JS 只有 `appendChild`,直接挂容器末尾会跑到危险区下面);④ 踩坑两条:块元素用 `<div>` 而不是 `<section>`(守卫按第一个 `</section>` 切片)、`<p class="meta-note">` 要显式收默认边距;⑤ 守卫别用关键词 `indexOf` 定位置 —— 说明性注释里也会提到「危险操作」,会搜到注释的位置。

- v20(2026-09-12):**删掉「当前题库:xxx」+ 修改名不刷新**(👤 反馈)。① 「题库设置」页顶部那行「当前题库:xxx」删除 —— 库名在编辑器标题栏已经写着,同一屏再挂一遍是噪音(它也正是"改名后屏幕上还留着旧名"的现场)。② bug:在编辑器里重命名后,标题/列表/版本记录仍是旧名。根因是 `renameBank()` 只挪了 `questionBanks` 的键,没改 `state.editBankName` —— 旧键已不存在,`currentEditBank()` 直接返回空数组,表现为**「改个名,这库的题全没了」**;同时按库名存的**版本快照**也要一起迁移,否则面板显示"暂无记录"而历史成孤儿(新增 `renameBankVersions()`)。

- v19(2026-09-12):**「保存」跟着选中的那一道走**(👤 要求)。动作行里的 `#editor-save-btn`「保存本题」删除;题号列表的每一行改为 **✕(左) → 正文 → 保存(右)**,两颗按钮**只对选中那一行现身**。关键实现:非选中行用 **`visibility:hidden` 占位**而不是不渲染 —— 行宽恒定,换题时文字不重排、按钮也不会在手指底下挪窝(点第 3 题再点第 4 题时,✕ 位置不动)。同时修掉一个暗病:列表选中态原按 `children` 下标对号,「只看待补」筛掉行后会**错行点亮**,现改按 `data-idx` 对号。

- v18(2026-09-12):**修两个 bug**(👤 反馈)。① 从编辑器里点「重命名」,对话框被编辑器盖住、无法操作 —— 根因是所有 `.modal` 同为 `z-index:1000`,**同级只看 DOM 顺序**,而二级弹窗在 HTML 里都排在编辑器之前;改为**二级弹窗 1100 > 一级 1000**。② 删库后回收站要刷页面才更新 —— `deleteBank()` 漏调 `renderRecycleBin()`。新增 §3.8。

- v17(2026-09-12):**回收站改为悬浮菜单**(👤 要求):从题库页底部的折叠块移到「我的题库」标题行的**最右**(紧跟「＋ 创建题库」),点开是**绝对定位的悬浮面板**,不占文档流。踩坑:闭合的 `<details>` 在本机 chromium 上**仍会渲染 children**(实测 `open=false` 却有 44px 高、文字可读),故闭合态必须用 `.recycle-pop:not([open]) > .recycle-pop-panel { display:none }` **显式隐藏**,不能赌原生默认行为。

- v16(2026-09-11):**版本记录理顺 + 迁入题库设置**(👤 要求)。① 补上**删除单条版本**的能力(原来只能存、不能删,存错了只能等它被淘汰);② 修正存版时机 —— **只在确认真的会改动题目之前存**(去重先查有没有重复,没有就不存,否则空点一次就白占一个槽;每库只有 3 个槽);③ 版本区从库卡手风琴**移到编辑器的「题库设置」**标签页(它属于整库设置,和配色/重命名同类);④ 空态给文案说明"哪些操作会自动存版"。新增 §3.6。

- v15(2026-09-11):**表单文案与判断题口径**(👤 定调)。① 字段文案一律放到**输入框左边**(固定宽标签列 + 自适应字段,`display:flex` 实现,窄屏整体换行不横向滚动);② 删除「选项」标题(选项行与增删按钮本身已自明);③ 判断题提示改为 **A=正确、B=错误**,不再让用户填「对/错」(字段存的就是 A/B;填「对/错」仍被接受并归一,见 `editorSaveCurrent`)。

- v14(2026-09-11):**编辑器再收敛**(👤 定调)。① 标题栏只剩"库名居中 + 右上角关闭"(`position:absolute` 让库名**真正居中** —— flex 左右等宽做不到,因为关闭键只有一个);② **取消底栏**,「保存本题 / 新增题目 / 只看待补答案」三个常用动作移到**题目列表上方**的动作行;③ **取消「上一题 / 第 N 题 / 下一题 / 删除本题」**——题号列表常显且每行自带删除,列表本身就是导航;④ **题干 / 题型答案 / 选项 / 解释 / 解析合成一个表单区块,取消全部折叠**(原「题目解释/解析」的 details 移除);⑤ 题号列表**不再收起**(上一版的开合标题删除)。踩坑:我一度把「关闭」当成"底栏那颗按钮"整条删掉,其实只是移到标题栏 —— 功能必须留着。

- v13(2026-09-11):**编辑器改为两标签页 + 头部收矮**(👤 要求)。①「编辑题目」(题号列表 + 当前题) 与「题库设置」(整库) 拆成两个标签页,由 `data-tab` + CSS `:has(input:checked)` 表达;② 头部只留 关闭 / 库名 / 进度,整条压到 **44px**(标签条同高),动作全部下沉到标签页;③ 题号列表**每一项都带删除键**(👤 要求"按钮可以新增和删减"),带二次确认,手机触达 44px。踩坑:首屏若 `data-tab` 缺省会让两页**同时隐藏**(实测),故 HTML 给默认值 + JS 双保险。

- v12(2026-09-11):**题库编辑器重构(手机优先)**(👤 要求"易于触摸、逻辑合理、分区清晰")。原文见 §3.5:三段式(头部进度 / 唯一滚动主体 / **底部固定操作栏**);手机整屏、单列、**题号列表默认收起**由头部按钮拉出(选完自动收起)、所有可点元素 **≥44px**、输入框字号 ≥16px(防 iOS 聚焦缩放);**题目级操作与题库级操作彻底分开** —— 「删除本题」移出底部动作栏、跟着题号导航走,题库设置收进折叠区。顺带修了"只看待补时进度显示 3/3(实际只有 1 条)"的 bug。

- v11(2026-09-11):**题库卡改为"配色底 + 框"**(👤 定稿):去掉左侧 4px 主色装饰条,默认 = 白底 + 普通边框(与站内其它卡片一致),可选 5 色(蓝/绿/红/琥珀/青)。配色走 `data-color` + `:root` 成对令牌 `--c-bank-<名字>` / `--c-bank-<名字>-border`,**暗色另配一套同色相深值**(浅底直接套用会刺眼)。卡片内的底部按钮改半透明白底以适配任意底色。入口在题库编辑面板的「题库设置与管理」区,点一下即改即存。新增 §3.3 卡片配色小节。

- v10(2026-09-11):**题目卡片统一**(👤 要求):错题卡与收藏卡合并为一套 `.question-card` 结构 —— 题型 / 收藏 / 删除 一律移到**题干上方一行**(`.question-card-tags`,nowrap + 靠右动作,尺寸复用 `--tag-row-h`);收藏卡从"答案直接摊开"改为与错题卡相同的 `details` 主动回忆遮挡;删除键由实心红改为描边红(令牌 `--c-danger-hover` 随之删除)。**新增 7 条测试**(`tests/question-card.test.js`)+ 桩升级(`appendChild` 记录子节点,否则结构类断言无法进行)。标出 `errorbook.js`/`favorites.js` 内的旧卡片渲染为死路径。

- v9(2026-09-11):**题干上方标签行收口**(👤 要求「统一高度 + 减少上面空白」):三件(答题卡/题型/收藏)高度改由**单一令牌 `--tag-row-h`** 统一(基准 28px、手机 26px),字号一律 12px —— 原先各写各的,实测 28/20/22 高度 + 13/12/12 字号,一行高低参差。顶部空白:题干区到标题栏由 **64px 收到 32px**(`.quiz-container` 的 `padding-top` 24→16、`margin-top` 24→8;两者原本叠加)。**新增 2 条守卫**(等高、尺寸下限)。本次**无新增令牌**(复用既有变量机制,新增 `--tag-row-h`)。

- v8(2026-09-11):**修 bug —— 手机上题干与选项被压成窄柱**(👤 反馈"题干只有几个字时很窄很突兀")。真因与题干长短无关:`.quiz-container` 桌面用 `margin-left/right: auto` 居中,手机档把它变成 **flex 子项**后,flex 子项的 auto 横向边距会吃掉全部剩余空间、把元素压到最小内容宽 —— Chromium 实测 390px 手机上容器只有 **82px**(修复后 366px,与题干长短无关)。修法:手机档显式 `margin-left/right: 0`(题干容器与结果页都要)。**新增守卫**:手机档必须存在同时含 `display:flex` 与 `margin-left/right:0` 的容器规则。本次**无新增令牌**。

- v7(2026-09-11):**修 bug —— 「确认答案」变文案把状态栏挤高、按钮上下错位**(👤 反馈)。根治两手:①`#next-question-btn` 预留固定宽度(`min-width: 76px` + 文字居中),让两种文案**等宽**,从源头消除"按钮宽度会变";②进度/答题卡 + 题型 + 收藏整体移到题干上方标签行(`.question-tags`,一行三件、从左到右、`nowrap` + 子项 `flex:0 0 auto`),状态栏左区只剩「智能切题」。**新增铁律:标签行按钮的宽窄变化不得影响题干宽度;左区不得再放任何会随内容变宽的按钮**。本次**无新增令牌**。

- v6(2026-09-11):**修 bug —— 套题模式答题卡交卷前泄露对错**(👤 反馈)。改为四态:新增中性的 `picked`(套题交卷前"已选未判分"),`correct`/`wrong` 只在 `finishExam()` 置真的 `q_examGraded` 为真时出现;概览行交卷前只报"已选/未答"。判分台账清零收敛到新的 `resetGradingState()`(修掉"新一局继承上一局对错"的隐患)。本次**无新增令牌**。
